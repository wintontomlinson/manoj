2.4 Polymorphism

Polymorphism means "many forms." Overloading = same method name, different parameters. Overriding = child replaces parent's method.

Polymorphism ka matlab "many forms." Overloading = same naam, alag parameters. Overriding = child parent ka method replace karta hai.

Java
class Shape {
    void draw() { System.out.println("Drawing shape"); }
}
class Circle extends Shape {
    void draw() { System.out.println("Drawing circle"); }
}
public class Main {
    public static void main(String[] args) {
        Shape s = new Circle();
        s.draw();
    }
}
Step by step:
1. class Shape - parent with draw() method.
2. class Circle extends Shape - child overrides draw() with its own version.
3. Shape s = new Circle() - parent reference, child object (runtime polymorphism).
4. s.draw() - calls Circle's draw(), not Shape's. JVM decides at runtime. 1. class Shape - parent jismein draw() hai.
2. class Circle extends Shape - child apna draw() override karta hai.
3. Shape s = new Circle() - parent reference, child object (runtime polymorphism).
4. s.draw() - Circle ka draw() call hota hai, Shape ka nahi. JVM runtime pe decide karta hai.

2.5 Abstract Classes

An abstract class cannot be instantiated. It has abstract methods (no body) that child classes must implement.

Abstract class ka object nahi ban sakta. Ismein abstract methods hote hain (bina body) jo child classes ko implement karne padte hain.

3.3 try / catch / finally

5.1 Singleton Pattern

Singleton ensures only ONE instance of a class exists in the entire application. Private constructor prevents external creation.

    public static Database getInstance() {
        if (instance == null) instance = new Database();
        return instance;

}
public class Main {

Step by step:
1. private static Database instance - holds the single instance.
2. private Database() - private constructor, nobody outside can call new Database().
3. getInstance() - creates instance only if null, otherwise returns existing one.
4. db1 == db2 - both variables point to same object, prints true. 1. private static Database instance - single instance ko hold karta hai.
2. private Database() - private constructor, bahar se koi new Database() nahi kar sakta.
3. getInstance() - sirf null hone pe instance banata hai, warna existing return karta hai.
4. db1 == db2 - dono variables same object pe point karte hain, true print hota hai.

5.2 Factory Pattern

Factory Pattern creates objects without exposing creation logic. A factory method decides which class to instantiate based on input.

Factory Pattern objects banata hai bina creation logic expose kiye. Factory method input ke basis pe decide karta hai kaun si class instantiate karna hai.

Java
interface Shape { void draw(); }
class Circle implements Shape { public void draw() { System.out.println("Circle"); } }
class Square implements Shape { public void draw() { System.out.println("Square"); } }

class ShapeFactory {
    static Shape create(String type) {
        if (type.equals("circle")) return new Circle();
        if (type.equals("square")) return new Square();
        return null;
    }
}
public class Main {
    public static void main(String[] args) {
        Shape s = ShapeFactory.create("circle");
        s.draw();
    }
}
Step by step:
1. interface Shape - common type for all shapes.
2. ShapeFactory.create("circle") - client does not call new Circle() directly.
3. Factory decides which concrete class to return based on the string parameter.
4. Adding new shapes only changes the factory, not client code. 1. interface Shape - sab shapes ke liye common type.
2. ShapeFactory.create("circle") - client directly new Circle() nahi call karta.
3. Factory string parameter ke basis pe decide karta hai kaun si class return karna hai.
4. Nayi shapes add karne pe sirf factory change hoti hai, client code nahi.

5.3 Observer Pattern

Observer Pattern: when one object (subject) changes state, all dependent objects (observers) are notified automatically.

Observer Pattern: jab ek object (subject) ki state change hoti hai, sab dependent objects (observers) ko automatically notify kiya jaata hai.

Java
import java.util.*;
interface Observer { void update(String msg); }

class Channel {
    List<Observer> subs = new ArrayList<>();
    void subscribe(Observer o) { subs.add(o); }
    void publish(String msg) {
        for (Observer o : subs) o.update(msg);
    }
}
class User implements Observer {
    String name;
    User(String n) { name = n; }
    public void update(String msg) {
        System.out.println(name + " got: " + msg);
    }
}
public class Main {
    public static void main(String[] args) {
        Channel ch = new Channel();
        ch.subscribe(new User("Rahul"));
        ch.subscribe(new User("Priya"));
        ch.publish("New video!");
    }
}
Step by step:
1. interface Observer - contract: every observer must have update().
2. Channel - subject that maintains a list of subscribers.
3. subscribe() - adds observer to the list.
4. publish() - loops through all observers and calls update() on each.
5. Adding/removing observers does not change Channel's publish logic. 1. interface Observer - contract: har observer mein update() hona chahiye.
2. Channel - subject jo subscribers ki list maintain karta hai.
3. subscribe() - observer ko list mein add karta hai.
4. publish() - sab observers pe loop karke har ek pe update() call karta hai.
5. Observers add/remove karne se Channel ki publish logic nahi badalti.
