2.1 Classes, Objects & Constructors

Java 
class Student {
    String name;
    int roll;

    // Default constructor
    Student() { name = "Unknown"; roll = 0; }

    // Parameterized constructor
    Student(String name, int roll) {
        this.name = name;
        this.roll = roll;
    }

    // Copy constructor
    Student(Student other) {
        this.name = other.name;
        this.roll = other.roll;
    }

    void display() { System.out.println(name + " - " + roll); }
}

// Creating objects
Student s1 = new Student("Rahul", 101);
Student s2 = new Student(s1); // copy
Default constructor has no params. Parameterized takes arguments. Copy constructor duplicates another object. 'this' refers to current object.
Default constructor mein koi param nahi. Parameterized mein arguments lete hain. Copy constructor dusre object ki copy banata hai. 'this' current object ko refer karta hai.

2.2 Static Keyword

Java 
class Counter {
    static int count = 0; // shared by all objects
    Counter() { count++; }
    static void showCount() { System.out.println("Objects: " + count); }
}
new Counter(); new Counter();
Counter.showCount(); // Objects: 2
Static members belong to class, not object. Shared across all instances. Called via ClassName.method().
Static members class ke hote hain, object ke nahi. Sab instances mein share hote hain. ClassName.method() se call karte hain.

2.3 Inheritance (Single / Multilevel / Hierarchical)

Java 
// Single Inheritance
class Animal {
    void eat() { System.out.println("Eating..."); }
}
class Dog extends Animal {
    void bark() { System.out.println("Barking..."); }
}

// Multilevel: Animal -> Dog -> Puppy
class Puppy extends Dog {
    void play() { System.out.println("Playing..."); }
}

// Hierarchical: Animal -> Dog, Animal -> Cat
class Cat extends Animal {
    void meow() { System.out.println("Meow..."); }
}

// super keyword
class Vehicle { Vehicle(String t) { System.out.println("Vehicle: "+t); } }
class Car extends Vehicle { Car() { super("Car"); } }
Single: one parent. Multilevel: chain A->B->C. Hierarchical: multiple children from one parent. 'super' calls parent constructor/method.
Single: ek parent. Multilevel: chain A->B->C. Hierarchical: ek parent se multiple children. 'super' parent ka constructor/method call karta hai.

2.4 Abstract Classes & Interfaces

Java 
// Abstract class - cannot be instantiated
abstract class Shape {
    abstract double area(); // must be overridden
    void info() { System.out.println("I am a shape"); }
}
class Circle extends Shape {
    double r;
    Circle(double r) { this.r = r; }
    double area() { return Math.PI * r * r; }
}

// Interface with default & static methods
interface Drawable {
    void draw(); // abstract by default
    default void color() { System.out.println("Red"); }
    static void info() { System.out.println("Drawable interface"); }
}
class Square implements Drawable {
    public void draw() { System.out.println("Drawing Square"); }
}
Abstract class can have abstract + concrete methods. Interface is 100% abstract (before Java 8). Java 8+ allows default and static methods in interfaces.
Abstract class mein abstract + concrete dono methods ho sakte hain. Interface fully abstract hota tha (Java 8 se pehle). Java 8+ mein default aur static methods bhi interface mein aa sakte hain.

2.5 Polymorphism (Overloading & Overriding)

Java 
class Calculator {
    // Method Overloading (compile-time polymorphism)
    int add(int a, int b) { return a + b; }
    double add(double a, double b) { return a + b; }
    int add(int a, int b, int c) { return a+b+c; }
}

// Method Overriding (runtime polymorphism)
class Parent {
    void show() { System.out.println("Parent"); }
}
class Child extends Parent {
    void show() { System.out.println("Child"); } // overridden
}
Parent p = new Child(); // upcasting
p.show(); // "Child" - runtime decision
Overloading: same method name, different params (compile-time). Overriding: child redefines parent method (runtime). Use @Override annotation.
Overloading: same naam, different params (compile-time). Overriding: child parent ka method redefine karta hai (runtime). @Override annotation lagao.

2.6 final Keyword & instanceof

Java 
final int MAX = 100;        // constant variable

// instanceof - type checking
Animal a = new Dog();
if (a instanceof Dog) {

final variable = constant, final class = can't extend, final method = can't override. instanceof checks object type before casting.
final variable = constant, final class = extend nahi ho sakti, final method = override nahi ho sakta. instanceof casting se pehle type check karta hai.

3.2 Exception Handling (try/catch/finally/throw/throws)

Java 
public class ExceptionDemo {
    // throws declares exception
    static int divide(int a, int b) throws ArithmeticException {
        if (b == 0) throw new ArithmeticException("Cannot divide by 0");
        return a / b;
    }

    public static void main(String[] args) {
        try {
            int result = divide(10, 0);
        } catch (ArithmeticException e) {
            System.out.println("Error: " + e.getMessage());
        } finally {
            System.out.println("Done.");
        }
    }
}
try = risky code, catch = handle error, finally = always runs, throw = create exception, throws = declare in method signature.
try = risky code, catch = error handle karo, finally = hamesha chalta hai, throw = exception banao, throws = method signature mein declare karo.

3.3 Multiple Catch & Custom Exceptions

Java 
// Multiple catch blocks
try {
    int[] arr = new int[5];
    arr[10] = 50;
} catch (ArrayIndexOutOfBoundsException e) {
    System.out.println("Index out of bounds!");
} catch (Exception e) {
    System.out.println("General error");
}

// Custom Exception
class AgeException extends Exception {
    AgeException(String msg) { super(msg); }
}

static void checkAge(int age) throws AgeException {
    if (age < 18) throw new AgeException("Underage!");
}
Multiple catch handles different exceptions (specific first, general last). Custom exceptions extend Exception class for domain-specific errors.
Multiple catch mein pehle specific, baad mein general exception likho. Custom exceptions domain-specific errors ke liye Exception class extend karti hain.

3.4 Try-with-Resources & Checked vs Unchecked

Java 
// Try-with-resources (auto-closes resource)
try (Scanner sc = new Scanner(new File("data.txt"))) {
    while (sc.hasNextLine())
        System.out.println(sc.nextLine());
} catch (FileNotFoundException e) {
    System.out.println("File not found!");
}
// Scanner automatically closed after try block

// Checked: must handle (IOException, SQLException)
// Unchecked: optional (NullPointerException, ArithmeticException)
Try-with-resources auto-closes resources (implements AutoCloseable). Checked exceptions must be caught/declared. Unchecked are runtime errors.
Try-with-resources automatically resource close karta hai (AutoCloseable). Checked exceptions ko catch/declare karna zaroori hai. Unchecked runtime errors hain.

4.2 HashSet & TreeSet

Java 
// HashSet - no duplicates, unordered
HashSet<String> set = new HashSet<>();
set.add("Apple");
set.add("Banana");

4.3 HashMap & TreeMap

Java 
// HashMap - key-value pairs, unordered
HashMap<String, Integer> map = new HashMap<>();
map.put("Java", 90);
map.put("Python", 85);
System.out.println(map.get("Java")); // 90
map.containsKey("Python"); // true

// TreeMap - sorted by keys
TreeMap<String, Integer> tm = new TreeMap<>(map);

Iterator<Map.Entry<String,Integer>> it = map.entrySet().iterator();

HashMap key-value pairs O(1) access ke saath store karta hai. TreeMap keys sorted rakhta hai. Iterator safe traversal aur removal provide karta hai.

4.5 Threads (Thread class & Runnable)

Java 
// Method 1: Extend Thread class
class MyThread extends Thread {
    public void run() {
        for(int i=0; i<3; i++)
            System.out.println(getName() + ": " + i);
    }
}

// Method 2: Implement Runnable interface
class Task implements Runnable {
    public void run() {
        System.out.println("Task running: " + Thread.currentThread().getName());
    }
}

// Starting threads
new MyThread().start();
new Thread(new Task()).start();
Thread class: extend and override run(). Runnable interface: implement run() and pass to Thread. Always call start() not run().
Thread class: extend karo aur run() override karo. Runnable: run() implement karo aur Thread mein pass karo. Hamesha start() call karo, run() nahi.

5.1 AWT Basics (Frame, Button, Label, TextField, Events)

Java 
import java.awt.*;
import java.awt.event.*;

class AwtDemo extends Frame implements ActionListener {
    TextField tf;
    Label lbl;

    AwtDemo() {
        tf = new TextField(20);
        Button btn = new Button("Click");
        lbl = new Label("Output here");

        btn.addActionListener(this);
        setLayout(new FlowLayout());
        add(tf); add(btn); add(lbl);
        setSize(300, 200);
        setVisible(true);
    }

    public void actionPerformed(ActionEvent e) {
        lbl.setText("Hello, " + tf.getText());
    }
}
AWT is Java's original GUI toolkit. Frame is the window. ActionListener handles button clicks. FlowLayout arranges components left to right.
AWT Java ka original GUI toolkit hai. Frame window hai. ActionListener button clicks handle karta hai. FlowLayout components ko left to right lagata hai.

Java 
public class Database {

5.4 Factory Pattern

Java 
interface Shape { void draw(); }
class Circle implements Shape { public void draw() { System.out.println("Circle"); } }
class Square implements Shape { public void draw() { System.out.println("Square"); } }

class ShapeFactory {
    Shape getShape(String type) {
        if (type.equals("circle")) return new Circle();
        if (type.equals("square")) return new Square();
        return null;
    }
}
Shape s = new ShapeFactory().getShape("circle");
s.draw(); // Circle
Factory creates objects without exposing creation logic. Client uses factory method instead of 'new'. Promotes loose coupling.
Factory objects banata hai bina creation logic expose kiye. Client 'new' ki jagah factory method use karta hai. Loose coupling promote karta hai.

5.5 Observer Pattern

Java 
import java.util.*;

interface Observer { void update(String msg); }

class Channel {
    List<Observer> subs = new ArrayList<>();
    void subscribe(Observer o) { subs.add(o); }
    void notify(String msg) { for(Observer o : subs) o.update(msg); }
}

class User implements Observer {
    String name;
    User(String n) { name=n; }
    public void update(String msg) { System.out.println(name+": "+msg); }
}
Observer pattern: when subject changes state, all registered observers are notified. Used in event systems, notifications.
Observer pattern: jab subject ki state change ho, sab registered observers ko notify karo. Event systems, notifications mein use hota hai.

5.6 Builder Pattern

Java 
class Pizza {
    String size, cheese, topping;
    private Pizza(Builder b) { size=b.size; cheese=b.cheese; topping=b.topping; }

    static class Builder {
        String size, cheese, topping;
        Builder size(String s) { size=s; return this; }
        Builder cheese(String c) { cheese=c; return this; }
        Builder topping(String t) { topping=t; return this; }
        Pizza build() { return new Pizza(this); }
    }
}
Pizza p = new Pizza.Builder().size("Large").cheese("Mozzarella").build();
Builder separates object construction from representation. Method chaining makes code readable. Useful when constructor has many optional parameters.
Builder object construction ko representation se alag karta hai. Method chaining code readable banati hai. Jab constructor mein bahut optional params ho tab useful hai.
