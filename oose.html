Design Patterns
▼

Reusable solutions to common software design problems. Three types: Creational, Structural, Behavioral.

Software design problems ke reusable solutions. Teen types: Creational, Structural, Behavioral.

Singleton Factory Observer Strategy Builder Adapter

1. Singleton Pattern

Only ONE instance of a class exists. Use for: Database connection, Logger, Config manager.
Class ka sirf EK hi instance banta hai. Use: DB connection, Logger, Config manager.
Java
class Database {
    private static Database instance;
    private Database() {} // private constructor
    public static Database getInstance() {
        if (instance == null) instance = new Database();
        return instance;
    }
}

2. Factory Pattern

Creates objects without specifying exact class. Use for: Shape creation, Payment processing, Notification types.
Exact class bataye bina objects banata hai. Use: Shape creation, Payment processing, Notifications.
Java
interface Shape { void draw(); }
class Circle implements Shape { public void draw() { System.out.println("Circle"); } }
class Square implements Shape { public void draw() { System.out.println("Square"); } }

class ShapeFactory {
    static Shape create(String type) {
        if (type.equals("circle")) return new Circle();
        return new Square();
    }
}

3. Observer Pattern

When state changes, all subscribers get notified. Use for: Event systems, Notifications, UI updates.
State change hone pe sabhi subscribers ko notify karta hai. Use: Events, Notifications, UI updates.
Java
interface Observer { void update(String msg); }

class Channel {
    List<Observer> subs = new ArrayList<>();
    void subscribe(Observer o) { subs.add(o); }
    void notify(String msg) {
        for(Observer o : subs) o.update(msg);
    }
}

4. Strategy Pattern

Switch algorithms at runtime. Use for: Sorting strategies, Payment methods, Compression algorithms.
Runtime pe algorithm switch kar sakte ho. Use: Sorting, Payment methods, Compression.
Java
interface SortStrategy { void sort(int[] arr); }
class BubbleSort implements SortStrategy { public void sort(int[] a) { /*bubble*/ } }
class QuickSort implements SortStrategy { public void sort(int[] a) { /*quick*/ } }

class Sorter {
    SortStrategy strategy;
    void setStrategy(SortStrategy s) { strategy = s; }
    void execute(int[] arr) { strategy.sort(arr); }
}

5. Builder Pattern

Build complex objects step by step. Use for: Pizza orders, Query builders, Config objects.
Complex objects ko step by step banao. Use: Pizza order, Query builder, Config objects.
Java
class Pizza {
    String size, crust, topping;
    static class Builder {
        String size, crust, topping;
        Builder size(String s) { size=s; return this; }
        Builder crust(String c) { crust=c; return this; }
        Builder topping(String t) { topping=t; return this; }
        Pizza build() { return new Pizza(this); }
    }
}
// Usage: new Pizza.Builder().size("L").crust("thin").topping("cheese").build();

6. Adapter Pattern

Makes incompatible interfaces work together. Use for: Legacy code integration, Third-party library wrapping.
Incompatible interfaces ko saath kaam karata hai. Use: Purane code ko naye ke saath connect karna.
Java
interface MediaPlayer { void play(String file); }
class VlcPlayer { void playVlc(String f) { /*vlc*/ } }

class VlcAdapter implements MediaPlayer {
    VlcPlayer vlc = new VlcPlayer();
    public void play(String file) { vlc.playVlc(file); }
}

SOLID Principles
▼

Five design principles for writing clean, maintainable OOP code.

Paanch design principles jo clean aur maintainable OOP code likhne mein madad karte hain.

S — Single Responsibility Principle

A class should have only ONE reason to change (one job only).
Ek class ka sirf EK hi kaam hona chahiye (ek reason to change).
Java
// ✓ Correct: Each class has one job
class Invoice { double calculate() { return qty * price; } }
class InvoicePrinter { void print(Invoice i) { /*print*/ } }
class InvoiceSaver { void save(Invoice i) { /*save to DB*/ } }

O — Open/Closed Principle

Open for extension, closed for modification. Add new features without changing existing code.
Extension ke liye open, modification ke liye closed. Naya feature add karo bina purana code badle.
Java
// ✓ Correct: Add new shapes without modifying existing code
interface Shape { double area(); }
class Circle implements Shape { public double area() { return 3.14*r*r; } }
class Rect implements Shape { public double area() { return w*h; } }
// New shape? Just add new class implementing Shape!

L — Liskov Substitution Principle

Child class should work wherever parent class is used without breaking anything.
Child class ko parent ki jagah use karo toh kuch break nahi hona chahiye.
Java
// ✓ Correct: Any Bird subclass works where Bird is expected
class Bird { void eat() {} }
class Sparrow extends Bird { void fly() {} }
class Penguin extends Bird { void swim() {} }
// Both work as Bird - no broken behavior

I — Interface Segregation Principle

Don't force classes to implement methods they don't use. Use small, specific interfaces.
Classes ko un methods ko implement karne pe force mat karo jo unke kaam ke nahi. Chhote interfaces banao.
Java
// ✓ Correct: Small, focused interfaces
interface Printable { void print(); }
interface Scannable { void scan(); }
class Printer implements Printable { public void print() {} }
class AllInOne implements Printable, Scannable {
    public void print() {} public void scan() {}
}

D — Dependency Inversion Principle

Depend on abstractions (interfaces), not concrete classes. High-level modules shouldn't depend on low-level.
Concrete classes pe nahi, abstractions (interfaces) pe depend karo. High-level module low-level pe depend na kare.
Java
// ✓ Correct: Depend on interface, not concrete class
interface NotificationService { void send(String msg); }
class EmailService implements NotificationService {
    public void send(String msg) { /*email*/ }
}
class UserController {
    NotificationService service; // depends on interface!
    void register() { service.send("Welcome!"); }
}
