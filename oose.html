Design Patterns
▼

Design Patterns are reusable solutions to recurring software design problems. They are categorized into Creational, Structural, and Behavioral patterns.

Design Patterns baar-baar aane wale software design problems ke reusable solutions hain. Ye teen categories mein hain: Creational, Structural, aur Behavioral.

Singleton Factory Builder Adapter Observer Strategy
CategoryPatternPurposePurpose

StructuralAdapterMake incompatible interfaces work togetherIncompatible interfaces ko saath kaam karao

Java 
// Observer Pattern
interface Observer {
    void update(String message);
}

class Student implements Observer {
    String name;
    Student(String name) { this.name = name; }
    public void update(String msg) {
        System.out.println(name + " received: " + msg);
    }
}

class NoticeBoard {
    List<Observer> observers = new ArrayList<>();
    void subscribe(Observer o) { observers.add(o); }
    void post(String msg) {
        for (Observer o : observers) o.update(msg);
    }
}
Observer Pattern: When NoticeBoard posts a message, all subscribed Students get notified automatically. This is like YouTube subscriptions - you get notified of new videos.
Observer Pattern: Jab NoticeBoard pe message post hota hai, saare subscribed Students ko automatically notification milta hai. Ye YouTube subscription jaisa hai - new video aaye toh notification milta hai.

SOLID Principles
▼

SOLID principles are five guidelines for writing maintainable, scalable object-oriented code.

SOLID principles paanch guidelines hain jo maintainable aur scalable OOP code likhne mein madad karte hain.

S - Single Responsibility O - Open/Closed L - Liskov Substitution I - Interface Segregation D - Dependency Inversion
PrincipleMeaningMeaning
S One class = one job Ek class ka ek hi kaam hona chahiye
O Open for extension, closed for modification Class extend ho sake, par modify nahi karni chahiye
L Child should work wherever parent works Child class parent ki jagah kaam kar sake
I Small focused interfaces better than big ones Chhoti focused interfaces better hain badi wali se
D Depend on abstractions, not concrete classes Concrete classes pe nahi, abstractions pe depend karo
Java - SRP Example 
// BAD: One class doing everything
class Student {
    void calculateMarks() { /* ... */ }
    void printReport() { /* ... */ }
    void saveToDatabase() { /* ... */ }
}

// GOOD: Each class has single responsibility
class Student { void calculateMarks() { } }
class ReportPrinter { void print(Student s) { } }
class StudentRepository { void save(Student s) { } }
Java - DIP Example 
// Dependency Inversion: Depend on abstractions
interface NotificationService {
    void send(String message);
}

class EmailService implements NotificationService {
    public void send(String msg) {
        System.out.println("Email: " + msg);
    }
}

class SMSService implements NotificationService {
    public void send(String msg) {
        System.out.println("SMS: " + msg);
    }
}

// Depends on abstraction, not concrete class
class AlertSystem {
    NotificationService service;
    AlertSystem(NotificationService s) { this.service = s; }
    void alert(String msg) { service.send(msg); }
}
SOLID makes code easier to maintain and extend. SRP: Split large classes. OCP: Use polymorphism to add features. LSP: Proper inheritance hierarchy. ISP: Small interfaces. DIP: Use interfaces for dependencies.
SOLID se code maintain aur extend karna easy hota hai. SRP: Badi classes split karo. OCP: Features add karne ke liye polymorphism use karo. LSP: Sahi inheritance hierarchy. ISP: Chhoti interfaces. DIP: Dependencies ke liye interfaces use karo.
