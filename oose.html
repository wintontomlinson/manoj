Creational Patterns

Singleton Factory Builder
Java - Builder Pattern class Student { private String name, branch, college; private int roll; static class Builder { private String name, branch, college; private int roll; Builder name(String n) { name = n; return this; } Builder roll(int r) { roll = r; return this; } Builder branch(String b) { branch = b; return this; } Builder college(String c) { college = c; return this; } Student build() { return new Student(this); } } private Student(Builder b) { name = b.name; roll = b.roll; branch = b.branch; college = b.college; } } // Usage - readable & flexible Student s = new Student.Builder() .name("Rahul") .roll(101) .branch("MCA") .college("GGSIPU") .build();

Structural Patterns

Adapter Decorator
Java - Decorator Pattern interface Coffee { String getDescription(); double getCost(); } class SimpleCoffee implements Coffee { public String getDescription() { return "Simple Coffee"; } public double getCost() { return 50.0; } } class MilkDecorator implements Coffee { private Coffee coffee; MilkDecorator(Coffee c) { coffee = c; } public String getDescription() { return coffee.getDescription() + " + Milk"; } public double getCost() { return coffee.getCost() + 20.0; } } // Usage Coffee c = new MilkDecorator(new SimpleCoffee()); // "Simple Coffee + Milk" → ₹70.0

Behavioral Patterns

Observer Strategy
Java - Strategy Pattern interface SortStrategy { void sort(int[] arr); } class BubbleSort implements SortStrategy { public void sort(int[] arr) { // Bubble sort implementation System.out.println("Sorting with Bubble Sort"); } } class QuickSort implements SortStrategy { public void sort(int[] arr) { // Quick sort implementation System.out.println("Sorting with Quick Sort"); } } class Sorter { private SortStrategy strategy; void setStrategy(SortStrategy s) { strategy = s; } void sort(int[] arr) { strategy.sort(arr); } } // Swap strategy at runtime Sorter sorter = new Sorter(); sorter.setStrategy(new QuickSort()); sorter.sort(data);

SOLID Design Principles
▼

S - Single Responsibility Principle

A class should have only one reason to change.

Java // BAD - class does too much class Student { void saveToDatabase() { ... } void generateReport() { ... } void sendEmail() { ... } } // GOOD - separate responsibilities class Student { /* only student data */ } class StudentRepository { void save(Student s) {} } class ReportGenerator { void generate(Student s) {} } class EmailService { void send(String to, String msg) {} }

O - Open/Closed Principle

Open for extension, closed for modification.

Java // Open for extension via interfaces interface DiscountStrategy { double calculate(double amount); } class StudentDiscount implements DiscountStrategy { public double calculate(double amt) { return amt * 0.2; } } class FestivalDiscount implements DiscountStrategy { public double calculate(double amt) { return amt * 0.3; } } // Add new discount types without modifying existing code!

L - Liskov Substitution Principle

Subtypes must be substitutable for their base types.

Java class Bird { void eat() { System.out.println("Eating"); } } interface Flyable { void fly(); } // Sparrow can fly class Sparrow extends Bird implements Flyable { public void fly() { System.out.println("Flying"); } } // Penguin cannot fly - no Flyable interface class Penguin extends Bird { void swim() { System.out.println("Swimming"); } }

I - Interface Segregation Principle

Clients should not be forced to depend on interfaces they don't use.

Java // BAD - fat interface interface Worker { void work(); void eat(); void sleep(); } // GOOD - segregated interfaces interface Workable { void work(); } interface Eatable { void eat(); } interface Sleepable { void sleep(); } class Human implements Workable, Eatable, Sleepable { ... } class Robot implements Workable { ... } // No eat/sleep!

D - Dependency Inversion Principle

Depend on abstractions, not concretions.

Java // Abstraction interface NotificationService { void send(String message); } // Concrete implementations class EmailNotification implements NotificationService { public void send(String msg) { /* send email */ } } class SMSNotification implements NotificationService { public void send(String msg) { /* send SMS */ } } // High-level module depends on abstraction class UserController { private NotificationService notifier; UserController(NotificationService ns) { notifier = ns; // Inject dependency } void register() { notifier.send("Welcome to MCA!"); } }
